# Paseo child image build evidence

The Arch sibling produced `alicedev/paseo-arch:local` as `amd64/linux`; the current
BridgeCore harness source was copied only for this smoke and removed afterwards. The
child build command was:

```text
docker build --platform linux/amd64 --pull=false -f deploy/paseo/Dockerfile -t alicedev/paseo:deploy-smoke .
```

Observed build steps:

```text
[1/5] FROM docker.io/alicedev/paseo-arch:local@sha256:6f992f78cfed0b9ead61b08d53f1b88ed5dcc4f943d03512689a1937d45073d9
[2/5] COPY harness/dist/omp-extension/ /opt/alicedev/omp-extension/
[3/5] COPY harness/dist/reply-cli/alicedev-reply /usr/local/bin/alicedev-reply
[4/5] COPY deploy/paseo/entrypoint-hook.sh /usr/local/bin/alicedev-paseo-entrypoint
[5/5] RUN ... chmod ... mkdir ... cat paseo-config.json
amd64/linux 831598320 bytes
```

This proves the child `FROM` resolves the locally built Arch image, both harness outputs
are copied, the hook is executable, and the provider configuration is embedded. The
smoke image was removed after the build; no container or volume was started.
