The container reports `restart=always`, uses named volume `alicedev_tg_cli_data` mounted at `/data`, and `tg --version` returns `tg-cli, version 0.6.0`.

Restart proof:
1. Wrote a marker to `/data/session-persistence-check`.
2. Ran `docker compose -f deploy/tg-cli/docker-compose.yml stop` then `start`.
3. Read the marker successfully after restart; container status was `running` and restart policy remained `always`.

Telegram auth note: this isolated volume had no pre-seeded Telegram account session, so no real account was used. The first run must authenticate with `docker exec -it alicedev-tg-cli tg chats`; the resulting `/data/tg_cli.session` persists in the named volume alongside the local cache. `tg photo --msg ... --out ...` is installed and returns a clear cache/auth error until that seed and a cached media message exist.
