6. Admin share link
--------------------
The first link attempts exposed two exact deployment observations:
  - `/链接 s_6qwymgt26a` after an AstrBot restart returned
    `当前群没有可分享的活动会话。` because the new WebChat conversation had a
    different generated chat key than the pre-restart session.
  - `/链接 s_3sofon7jse` found the session but returned
    `该会话尚未准备好分享。` because production MCP create/list responses omitted
    serverId, leaving sessions.server_id NULL.

Fixes applied and deployed
---------------------------
1. `bot/alicedev/commands/requirement.py`: generic registration now iterates
   `services.templates.all()`, filters `Command` triggers, and registers each
   frontmatter command/aliases/description with a parameterized template handler.
   Existing `record: requirement` behavior remains intact; `/需求` post-fix proof is
   `08-requirement-after-fix.png` (session s_f6lzvba45v).
2. `bot/alicedev/paseo/mcp.py`: when MCP omits serverId, fetch/cache authenticated
   `GET /api/status.serverId` and propagate it into AgentHandle/session persistence.

Deployment actions: rsync each changed file to `/srv/alicedev/...` and restart
`alicedev-astrbot`. One intermediate restart exposed and then fixed a missing
`CommandSpec.description` argument; the final startup log reported
`alicedev initialized: 10 commands, 4 templates`.

- Share URL was not opened and report URL was not opened; browser share/report
