Gateway Paseo proxy evidence (local runtime)
===============================================

The Paseo daemon ran on :6768 with its web UI enabled and password authentication. The gateway ran on :8080 and proxied an authenticated browser session.

HTTP:
  gateway_status 200 has_server_status True
  direct_status_without_auth 401

WebSocket through gateway:
  browser_protocol None
  first_message TEXT {"type":"session","message":{"type":"status","payload":{"status":"server_info"...}}
  hello_ack True

The gateway injected Paseo Authorization/Host/Origin and the upstream bearer subprotocol during its separate upstream handshake; the browser handshake did not expose the bearer protocol. Paseo logs showed a client connecting via hello with host localhost:8080 and origin https://localhost:8080, with no host/origin rejection.

Compressed Paseo assets were also checked through the gateway with auto-decompression disabled: gzip and br responses remained raw and identity returned 200. A real browser reload then loaded the Paseo shell with CSS/JS 200 responses.
